## 1. 소스 구조

빌드 도구와 프레임워크 없이 순수 HTML/CSS/JavaScript로 만들었습니다. 파일을 웹서버에 올리면 바로 동작합니다.

```
01_src/
├─ login.html         로그인: Supabase Auth (이메일 + 비밀번호)
├─ admin.html         관리: 초기 데이터 업로드, 본인 비밀번호 재설정 메일 (로그인 필수)
├─ index.html         대시보드: 통계 카드 4개, 자산군 도넛/단계 막대 차트, 최근 딜
├─ deals.html         딜 목록: 목록 뷰 + 칸반 뷰(드래그로 단계 변경), 검색·필터
├─ deal-new.html      새 딜 입력 폼
├─ deal-detail.html   딜 상세: 정보 편집, 단계 바, 메모 타임라인, 첨부파일, 단계 이력
├─ portfolio.html     진행경과: 딜별 단계 소요일수 타임라인
├─ css/style.css      전체 스타일 (사이드바, 칸반, 타임라인)
├─ js/config.js       ★ 환경 설정 (데모모드, API 주소/키, 로그인 메일 도메인, 팀원)
├─ js/common.js       ★ 공통 모듈: 상수, 데이터 접근 함수, 유틸, 사이드바
├─ js/seed-data.js    데모 모드 초기 데이터 (엑셀 이관 딜 247건)
└─ vendor/            외부 라이브러리 로컬 사본 (Bootstrap 5.3.2, Font Awesome 6.5.0, Chart.js 4.4.1, supabase-js 2)
```

- 각 HTML은 `config.js` → `seed-data.js` → `common.js` 순으로 로드한 뒤, 페이지 전용 스크립트를 인라인으로 가집니다.
- **DB 접근은 모두 `common.js`의 함수를 통해서만** 합니다. 화면 코드는 Supabase를 직접 호출하지 않습니다.
- 각 함수는 `DEMO_MODE` 값에 따라 localStorage(데모) 또는 Supabase를 사용합니다.

## 2. 데이터 접근 계층 (`js/common.js`)

백엔드를 Supabase가 아닌 사내 API로 바꾸는 경우(배포가이드 B안) **아래 함수들의 내부만 교체**하면 화면은 그대로 동작합니다.
모든 함수는 `async`이며 실패하면 예외를 던집니다. 화면에서 `showToast`로 오류를 표시합니다.

| 함수 | 인자 | 반환 | 테이블 | 권장 REST API (B안) |
|---|---|---|---|---|
| `getDeals(filters)` | `{asset_class, assigned_to, current_stage, search}` 선택 | 딜 배열 (created_at 내림차순) | deals | `GET /api/deals?asset_class=&assigned_to=&stage=&q=` |
| `getDeal(id)` | 딜 id | 딜 객체 | deals | `GET /api/deals/{id}` |
| `createDeal(data)` | 딜 필드 객체 | 생성된 딜 | deals + stage_history | `POST /api/deals` |
| `updateDeal(id, data)` | id, 변경 필드 | 수정된 딜 | deals | `PATCH /api/deals/{id}` |
| `deleteDeal(id)` | id | 없음 | deals (하위 CASCADE) | `DELETE /api/deals/{id}` |
| `changeStage(id, stage)` | id, 새 단계 | 없음 | deals + stage_history | `POST /api/deals/{id}/stage` |
| `getStageHistory(dealId)` | 딜 id | 이력 배열 (시간 오름차순) | deal_stage_history | `GET /api/deals/{id}/history` |
| `addStageHistory(dealId, stage, by)` | | 없음 | deal_stage_history | (changeStage에 포함) |
| `getNotes(dealId)` | 딜 id | 메모 배열 (최신순) | deal_notes | `GET /api/deals/{id}/notes` |
| `createNote(dealId, text, author)` | | 생성된 메모 | deal_notes | `POST /api/deals/{id}/notes` |
| `deleteNote(noteId)` | | 없음 | deal_notes | `DELETE /api/notes/{id}` |
| `getFiles(dealId)` | 딜 id | 파일 메타 배열 | deal_files | `GET /api/deals/{id}/files` |
| `uploadFile(dealId, file)` | 딜 id, `File` 객체 | 파일 메타 | Storage + deal_files | `POST /api/deals/{id}/files` (multipart) |
| `deleteFile(fileId, path)` | | 없음 | Storage + deal_files | `DELETE /api/files/{id}` |

필드명과 타입은 `02_db/01_schema.sql`과 같습니다. API 응답의 JSON 키를 **DB 컬럼명 그대로(snake_case)** 두면 화면 수정이 없습니다.

단계·자산군·인입경로 값 목록은 `common.js` 상단 상수(`STAGES`, `ASSET_CLASSES`, `INTAKE_CHANNELS`, `FINAL_RESULTS`)와 DB CHECK 제약이 **같아야** 합니다. 값을 추가할 때는 두 곳을 함께 수정하세요.

### 3-1. 사용자 인증 — ✅ 반영 완료 (2026-10-01)

**이전 상태**: `config.js`의 `CURRENT_USER`가 메모 작성자·단계 변경자·파일 업로더로 기록됐습니다.
설정 파일만 고치면 타인 명의로 기록을 남길 수 있었습니다. 또한 로그인 성공 표시를
`localStorage`에 남기는 방식이라, 개발자도구로 그 값을 넣으면 로그인 없이 통과됐습니다.

**현재**:
- `performLogin()` → `supabase.auth.signInWithPassword()`. 비밀번호는 Auth가 해시로 보관합니다.
- `CURRENT_USER`와 `ADMIN_PASSWORD`는 **삭제**했습니다. 기록에 남는 이름은
  `currentUserName()`(로그인한 사용자)로 자동 결정됩니다. **되살리지 마세요.**
- 진입 차단: `common.js` 하단에서 `hasStoredSession()`(동기, 즉시 차단) →
  `guardPage()`(서버 세션 검증). `login.html`만 예외입니다.
- 앱에는 타인의 비밀번호를 변경하는 기능이 **없습니다**. 계정 추가·초기화는
  Supabase 대시보드(Authentication > Users)에서만 수행합니다.
- 화면 쪽 차단은 편의이며, **실제 접근 통제는 3-3의 RLS**가 담당합니다.

**남은 결정 사항 (IT팀)**:
- 사내 SSO/AD 연동으로 교체할지 여부. 교체 시 `common.js`의
  `performLogin` / `getSession` / `guardPage` / `userFromSession` 네 함수만 바꾸면 됩니다.
- 권한 분리(명세서 2장: 팀장만 딜 삭제): 현재는 로그인한 팀원 모두 삭제 가능합니다.
  역할 기반 제한 예시는 `02_db/01_schema.sql` 6장 하단 주석에 있습니다.
- 이메일 자가 가입 차단: Authentication > Providers > Email 에서
  `Enable email signup`을 끄지 않으면 외부인이 스스로 계정을 만들 수 있습니다.

### 3-2. XSS: HTML 이스케이프 — ✅ 반영 완료 (2026-10-01)

**이전 상태**: 딜명·GP명·메모·파일명 등 외부에서 들어온 글자를 템플릿 문자열로
`innerHTML`에 그대로 넣고 있었습니다. 글자에 HTML 태그가 섞여 있으면 그대로 실행됩니다.

**현재**:
- `common.js`에 `escapeHtml()`을 추가하고 출력 지점 30여 곳에 적용했습니다.
- `onclick` 속성에 값을 끼워 넣던 두 곳(딜 삭제 버튼, 첨부 삭제 버튼)은
  `data-*` 속성 + 이벤트 위임으로 바꿨습니다. 속성 조립 방식에서는 값에 따옴표가
  들어가면 속성을 벗어나 임의 코드가 실행될 수 있어, escape만으로는 부족합니다.
  - `deals.html`의 목록은 행(`<tr>`)에 상세화면 이동 `onclick`이 있으므로,
    삭제 버튼 위임 리스너를 **캡처 단계**(`addEventListener(..., true)`)로 등록해
    행 이동보다 먼저 처리합니다. 거품 단계로 바꾸면 삭제 모달이 뜨지 않습니다.
- 줄바꿈을 `<br>`로 바꾸는 곳은 **escape를 먼저** 하고 그다음 치환합니다
  (순서가 바뀌면 escape가 무의미해집니다).

**검사 방법**: 화면 코드를 고친 뒤 아래를 돌려 0건인지 확인하세요.
```
python3 tools/check_xss.py
```
사용자 입력 필드를 escape 없이 출력하는 곳을 전수 검사합니다.
(이 스크립트와 브라우저 테스트는 전달 패키지에는 포함되지 않습니다. 소스 저장소에 있습니다.)

**남은 사항**: `STAGES` 상수를 `onclick`에 넣는 3곳
(`deal-detail.html`, `deal-new.html`, `portfolio.html`)은 코드에 고정된 값이므로
사용자 입력이 아닙니다. 외부 값으로 바꾸게 되면 그때 함께 처리해야 합니다.

### 3-3. DB 접근 통제 (RLS) — ✅ 반영 완료 (2026-10-01)

**이전 상태**: `01_schema.sql`은 RLS를 **끈 상태**로 두고 잠금 정책을 주석 처리했으며,
"운영 전에 활성화하세요"라는 주석만 달려 있었습니다. 주석은 실행되지 않습니다.
anon 키는 브라우저에 노출되므로, 내부망이라도 API 주소와 키를 아는 사람은
누구나 딜 데이터를 조회·수정·삭제할 수 있는 상태였습니다.

**현재**: `01_schema.sql` 6장이 **잠긴 상태를 기본값**으로 바뀌었습니다.
- 4개 테이블 모두 RLS 활성화, 정책은 `TO authenticated` 전용
- `REVOKE ALL ... FROM anon` 으로 비로그인 권한 회수 (두 겹 차단)
- 권한은 화면이 실제로 수행하는 동작과 일치시켰습니다
  (`deals` 조회·추가·수정·삭제 / `deal_stage_history` 조회·추가 /
   `deal_notes`·`deal_files` 조회·추가·삭제)
- 딜 삭제 시 하위 메모·이력·첨부는 외래키 `ON DELETE CASCADE`가 처리하며,
  이는 참조 무결성 작업이라 RLS·권한 검사를 거치지 않습니다.
  따라서 하위 테이블에 추가 권한을 줄 필요가 없습니다.
- `02_storage_bucket.sql`의 `anon` 허용도 제거하고 버킷을 비공개로 고정했습니다.

**확인 쿼리** (설치 후 실행 권장):
```sql
SELECT tablename, rowsecurity FROM pg_tables
WHERE schemaname='public'
  AND tablename IN ('deals','deal_stage_history','deal_notes','deal_files');
-- rowsecurity 가 네 줄 모두 true 여야 정상

SELECT tablename, policyname, roles, cmd FROM pg_policies
WHERE schemaname IN ('public','storage') ORDER BY tablename, policyname;
-- roles 에 anon 이 없어야 정상
```

**남은 사항**: 역할 분리(팀장만 삭제)는 미반영입니다. 적용 예시는
`01_schema.sql` 6장 하단 주석에 있습니다. 웹서버 IP 제한(VDI 대역만 허용)은
RLS와 별개로 병행을 권장합니다.

### 3-4. 첨부파일 다운로드

버킷이 비공개이므로 서명 URL로 내려받아야 합니다. `common.js`에 아래 함수를 추가하고 `deal-detail.html`의 파일 항목(203행)에 다운로드 버튼을 연결합니다.
```js
async function getFileUrl(filePath) {
  const { data, error } = await getSB().storage.from('deal-files').createSignedUrl(filePath, 60);
  if (error) throw error;
  return data.signedUrl;
}
```

### 3-5. 한글 파일명 업로드 — ✅ 반영 완료 (2026-10-01)

**이전 상태**: `uploadFile`이 `${dealId}/${Date.now()}_${file.name}`을 Storage 키로 썼습니다.
Supabase Storage 키는 한글 등 비ASCII 문자를 거부할 수 있어 업로드가 실패했고,
그 경로가 화면의 `onclick` 속성에 들어가 3-2의 주입 경로가 되기도 했습니다.

**현재**: 키에서 원본 파일명을 제거했습니다. 확장자만 안전한 문자로 뽑아 씁니다.
```js
const ext  = (file.name.match(/\.([A-Za-z0-9]{1,10})$/) || ['', ''])[1].toLowerCase();
const rand = Math.random().toString(36).slice(2, 8);
const path = `${dealId}/${Date.now()}_${rand}${ext ? '.' + ext : ''}`;
```
보여줄 이름은 `deal_files.file_name`에 원본 그대로 저장하므로 화면 표시는 달라지지 않습니다.

**주의**: 이 변경 이전에 업로드된 파일의 경로에는 원본 파일명이 남아 있습니다.
삭제·다운로드는 저장된 경로를 그대로 쓰므로 동작에 문제는 없습니다.

### 3-6 · 3-7. 단계 변경 원자성 / 오류 처리

- `changeStage`는 `deals` 수정과 `deal_stage_history` 추가를 따로 호출합니다. DB 트리거(`current_stage` 변경 시 이력 자동 삽입)나 RPC 함수 하나로 묶는 것을 권장합니다.
- `addStageHistory`와 `deleteFile`의 Supabase 응답 `error`를 확인해서 예외를 던지도록 수정합니다.
