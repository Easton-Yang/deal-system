# 딜 관리 시스템 — 내부 VDI 배포 가이드

> 대상: IT팀 (인프라/개발 담당) · 버전 v1.0 · 작성: 자산운용팀

---

## 1. 한눈에 보기

현재 초안은 **HTML/JavaScript 화면 5개 + Supabase(PostgreSQL 기반 백엔드)** 구조입니다.
화면은 빌드 과정이 없는 정적 파일이라 웹서버에 복사하면 되고, 백엔드만 내부에 설치하면 됩니다.

```
 [VDI 브라우저 (Chrome/Edge)]
          │  HTTPS
          ▼
 [내부 웹서버  nginx 또는 IIS]
   ├─ /             → 01_src 정적 파일 (화면)
   └─ /rest/v1/     ┐
      /storage/v1/  ├→ 역방향 프록시
      /auth/v1/     ┘
          │
          ▼
 [Self-hosted Supabase (Docker)]
   Kong(API 게이트웨이) · PostgREST · Storage API · PostgreSQL 15
```

## 2. 초안 대비 바뀐 점 (이 패키지에 반영된 것)

| 항목 | 초안 (개인 PC 테스트) | VDI 배포용 (이 패키지) | 상태 |
|---|---|---|---|
| 화면 라이브러리 | 인터넷 CDN에서 로드 | `01_src/vendor/` 로컬 파일 참조 | ✅ 완료 (라이브러리 파일 포함, 외부 요청 0건 확인) |
| 데이터 저장 | Supabase 클라우드(해외) 또는 브라우저 저장 | **사내 서버**에 Supabase 설치 | ⬜ IT 설치 필요 |
| 사용자 식별 | `config.js`에 이름 직접 입력 | 사내 인증(SSO/AD) 연동 권장 | ⬜ IT 결정 필요 |

> 딜 정보(투자 규모, 상대방, 검토 의견)는 대외비이므로 외부 클라우드에 저장하지 않고 **내부 서버에만 저장**하는 것을 전제로 합니다.

## 3. 백엔드 방식 선택

| | **A. Self-hosted Supabase (권장)** | B. 사내 표준 스택으로 재구현 |
|---|---|---|
| 내용 | 오픈소스 Supabase를 Docker로 내부 서버에 설치 | 사내 표준(Spring 등) API + 사내 DB |
| 화면 코드 수정 | **없음** (`config.js` 주소만 변경) | `js/common.js` 데이터 함수 교체 |
| 소요 | 설치·설정 1~2일 | API 개발 1~2주 |
| 적합한 경우 | Docker 사용 가능, 빠른 오픈 | 사내 표준·보안 정책상 Docker 불가 |

B안은 `개발_인수인계_노트.md` 2장(데이터 함수 ↔ API 매핑)을 참고하세요.

## 4. 서버 요구사항 (A안 기준, 사용자 4명)

| 항목 | 최소 | 비고 |
|---|---|---|
| OS | Ubuntu 22.04 / RHEL 9 | Docker Engine 24+, Docker Compose v2 |
| CPU / RAM | 2 vCPU / 4 GB | 미사용 서비스를 제외하면 여유 있음 |
| 디스크 | 50 GB | DB + 첨부파일. 첨부 증가 시 확장 |
| 네트워크 | VDI 대역 → 웹서버 443 | 외부 인터넷 연결 불필요 (설치 이미지 반입 후) |

## 5. 설치 절차 (A안)

### 5-1. 외부 파일 반입 (인터넷 PC에서)

1. **화면 라이브러리**: 이미 `01_src/vendor/`에 들어 있습니다 (반입 심사용 해시 목록 `vendor/SHA256SUMS.txt`). 다시 받아야 할 때만 `03_deploy/fetch-vendor.ps1`을 실행합니다.
2. **Supabase Docker 이미지**:
   ```bash
   git clone --depth 1 https://github.com/supabase/supabase
   cd supabase/docker
   docker compose pull
   docker save $(docker compose config --images) -o supabase-images.tar
   ```
   `supabase/docker` 폴더와 `supabase-images.tar`를 내부 서버로 반입합니다.

### 5-2. Supabase 설치 (내부 서버)

```bash
docker load -i supabase-images.tar
cd supabase/docker
cp .env.example .env
```

`.env`에서 반드시 바꿀 값:

| 변수 | 설명 |
|---|---|
| `POSTGRES_PASSWORD` | DB 비밀번호 (강력한 값) |
| `JWT_SECRET` | 32자 이상 임의 문자열 |
| `ANON_KEY`, `SERVICE_ROLE_KEY` | `JWT_SECRET`으로 서명한 키 (Supabase 문서의 키 생성 방법 참고) |
| `DASHBOARD_USERNAME`, `DASHBOARD_PASSWORD` | 관리 화면(Studio) 로그인 |
| `SITE_URL`, `API_EXTERNAL_URL` | 내부 서비스 주소 (예: `https://dealsys.사내도메인`) |

이 시스템은 **DB·REST API·Storage**만 사용합니다. `realtime`, `functions`, `analytics`, `vector`, `imgproxy`는 `docker-compose.yml`에서 제외해도 됩니다. (자원 절약, 공격 표면 축소)

```bash
docker compose up -d
docker compose ps        # 모두 healthy 확인
```

### 5-3. DB 생성

Studio(`http://서버:8000`, 대시보드 계정) → SQL Editor에서 순서대로 실행:

1. `02_db/01_schema.sql`: 테이블 4개, 제약조건, 인덱스, 트리거 (**최초 1회만**. 다시 실행하면 제약조건 중복 오류가 납니다)
2. `02_db/02_storage_bucket.sql`: 첨부파일 버킷 `deal-files`
3. `02_db/03_initial_data.sql`: 실제 딜 247건 + 단계이력 (엑셀 이관분, **1회만**)

또는 psql:
```bash
docker exec -i supabase-db psql -U postgres -d postgres < 01_schema.sql
docker exec -i supabase-db psql -U postgres -d postgres < 02_storage_bucket.sql
docker exec -i supabase-db psql -U postgres -d postgres < 03_initial_data.sql
```

**초기 데이터 참고**: 엑셀 원본(포트폴리오현황보고 딜 접수목록)에 없는 항목은 담당자 `미배정`, 인입경로 `기타`, 딜 규모 비움으로 들어갑니다. 엑셀에 단계별 날짜가 없어서, 이관 딜의 단계 이력은 모두 접수일 기준으로 기록됩니다.

### 5-4. 화면 배포

1. `01_src/` 전체를 웹서버 루트에 복사 (`vendor/` 포함)
2. 웹서버 설정: Linux는 `03_deploy/nginx.conf.sample`, Windows IIS는 `03_deploy/web.config`
3. `js/config.js` 수정:
   ```js
   const DEMO_MODE = false;
   const SUPABASE_URL = 'https://dealsys.사내도메인';   // 웹서버 주소 (프록시 사용 시)
   const SUPABASE_ANON_KEY = '.env 의 ANON_KEY';
   ```

### 5-5. 동작 확인

| 확인 | 기대 결과 |
|---|---|
| VDI에서 `https://dealsys.사내도메인` 접속 | 대시보드 표시, 아이콘·차트 정상 (아이콘이 □로 보이면 vendor 폰트 누락) |
| 좌측 상단 배지 | **라이브** (데모모드이면 `DEMO_MODE` 확인) |
| 새 딜 입력 → 저장 | Studio에서 `deals`, `deal_stage_history` 행 생성 확인 |
| 딜 상세 → 파일 추가 | Storage `deal-files` 버킷에 파일 생성 |
| 브라우저 개발자도구 Network | 외부 도메인 요청 **0건** |

전체 기능 검증은 `딜관리시스템_기능요구사항명세서_v1.0.docx` 7장 QA 체크리스트를 사용합니다.

## 6. 운영

**백업** (일 1회 권장)
```bash
# DB
docker exec supabase-db pg_dump -U postgres -d postgres -n public -Fc > dealsys_$(date +%F).dump
# 첨부파일 (Storage 볼륨)
tar czf dealsys_files_$(date +%F).tgz supabase/docker/volumes/storage
```

**복구 테스트**는 오픈 전 1회 수행해 주세요.

**설정 변경**: 팀원 추가·변경은 `js/config.js`의 `TEAM_MEMBERS`만 수정하면 됩니다. 빌드나 재시작은 필요 없습니다.

## 7. 데모 모드 (DB 없이 화면 확인)

`config.js`에서 `DEMO_MODE = true`로 두면 서버 없이 실제 딜 247건(`js/seed-data.js`)으로 모든 화면을 확인할 수 있습니다. 데이터는 해당 브라우저에만 저장됩니다. 개발 착수 전 화면 흐름 파악용으로 사용하세요.
